# 项目区说明

项目是**有交付物、有下一步、可以判断死活**的行动。一个项目一个目录。

## 目录形状

```text
05 项目/
  2026/
    2026-<项目名>/
      2026-<项目名>-项目主页.md   ← 必需，type: project
      2026-<项目名>-方案.md       ← 可选，type: project_doc
      2026-<项目名>-复盘.md       ← 结束时写，type: review
```

- 项目主页文件名固定为 `<项目名>-项目主页.md`，不要叫「项目主页」，否则全库会出现一堆同名文件。
- 年份目录用 `2026`，项目目录用 `2026-项目名`。跨年项目放在启动年份。
- 项目内文档用 `<项目名>-<文档名>.md`。

## 项目主页写什么

1. 一句话目标（做完之后世界有什么不同）
2. 背景与约束
3. SMART 目标
4. 关键结果（复选框**由作者自己勾**，AI 不代勾）
5. 里程碑
6. 下一步（具体到一个动作）
7. 相关文档与方法论依据
8. 状态记录
9. 复盘（结束时填）

## 状态

| status | 含义 | 判据 |
|---|---|---|
| `待启动` | 已立项，还没动手 | 没有真实动作 |
| `进行中` | 正在推进 | 过去 30 天有动作，且有下一步 |
| `暂停` | 主动停下 | 写清原因与重启条件 |
| `已完成` | 交付物已产生 | 有复盘 |
| `已归档` | 不再推进 | 移到 `99 归档/C 项目/` |

**判据是动作，不是文档。** 不要用「主页两周没更新」推断项目死了，也不要用「主页写得很完整」推断项目活着。看提交、看交付物、看日历。

## 审计会提醒

- `B13`：项目主页 / 项目文档路径或命名不符合 `05 项目/<年份>/<年份-项目名>/...`。
- `B14`：`status: 已归档` 但文件还在 `05 项目`，应移入 `99 归档`。
- `C3`：`status: 已完成` 但没有链接到 `type: review` 的复盘。
- `E3`：`进行中` 项目主页超过 30 天没更新。它只是**文档新鲜度**提醒，不代表项目停滞；请用 git / 交付物核实。
