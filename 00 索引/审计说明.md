# 审计说明

审计脚本回答一个问题：**这个库的结构是否还遵守它自己写的规则？** 它不评价内容好坏。

## 运行

在库根目录：

```bash
python3 tools/kb_audit.py
```

要求 Python 3.9+，只用标准库，不需要安装任何依赖。

### 常用参数

```bash
python3 tools/kb_audit.py --strict          # WARN 也让退出码非零
python3 tools/kb_audit.py --json            # 机器可读输出
python3 tools/kb_audit.py --root /path/to/vault
python3 tools/kb_audit.py --config tools/kb_config.json
```

### 退出码

| 码 | 含义 |
|---|---|
| `0` | 没有 FAIL（可能有 WARN） |
| `1` | 有 FAIL |
| `2` | 配置或运行错误 |

`--strict` 下，WARN 也会让退出码为 `1`。它适合“要求零 WARN”的库；如果你只想阻断 FAIL、把 WARN 留给人判断，CI 用普通模式，并把 `--json` 报告存档。

## 检查项

### A. 链接

- **断链**：`[[目标]]` 解析不到任何文件
- **歧义**：文件名在全库重复，且没有写够路径
- **半截路径**：像 `[[项目名/项目主页]]` 这种缺顶层目录的路径
- **锚点失效**：`[[文件#标题]]` 的标题不存在
- **标题含裸 `|`**：这种标题无法被章节链接指向（WARN）
- **文件名重复**：全库 basename 重复，即使当前没有链接指向（WARN）
- **嵌入失效**：`![[笔记]]` 的目标不存在；附件嵌入不检查

解析顺序与 Obsidian 一致：先相对当前文件目录 → 再相对库根 → 最后唯一文件名。重复文件名不会被猜，直接报歧义。

### B. frontmatter

> 仓库级文件（`README.md` / `CHANGELOG.md` / `CONTRIBUTING.md` / `SECURITY.md` / `CODE_OF_CONDUCT.md` / `CLAUDE.md`）豁免 frontmatter；它们不是知识库笔记。

- 文件无法按 UTF-8 读取（B0）
- 缺少 frontmatter 或必填字段
- `type` / `status` / `source_type` 不在词表内
- `status` 与 `type` 不兼容
- `type` 与所在目录不匹配
- 日期不是 `YYYY-MM-DD`
- `需复习` 缺少 `evidence_as_of`
- 使用了禁用标签
- `form` 不在词表内（B10）
- 同一别名被多个文件使用（WARN，可能导致链接指向不确定）

### C. 可达性与孤儿

- 从 `00 索引` 出发，是否能通过双链到达每一篇活跃笔记
- 是否有零入链的笔记

这两项是 WARN：有些笔记（例如日记）本来就不需要入链。

### D. 消化链路

- 02 是否被 03 引用
- 02 是否被 04 引用
- 03 是否引用 04

只做 WARN。**覆盖率不是 KPI**：技术细节本来就应该留在 02，不强行提拔。

### E. 陈旧与复习

- `updated` 超过 `stale_days`（默认 90 天）
- `需复习` 且 `evidence_as_of` 超过 `stale_days`：证据基线该更新了
- 带 `stale_exempt_tags`（默认 `示例`）标签的笔记跳过陈旧检查

只做 WARN。一个不常改的原创方法论，可能比每天更新的剪藏更健康；而 `需复习` 只是提醒复核，本身不报错。

### F. 占位与空笔记

- 正文含 `TODO` / `TBD` / `待补充` / `占位` / `{{...}}`
- 正文少于 4 行

只做 WARN。模板、索引、收件箱豁免。

## 输出

```text
知识库审计 · /path/to/vault
────────────────────────────────────────
A 链接            PASS
B frontmatter     FAIL  2 项
  [B2] status '已沉淀' 与 type 'topic' 不兼容  → 03 主题笔记/某篇.md
...
C 可达性          WARN  1 项
...
结果：FAIL（2 errors, 1 warning）
```

FAIL 需要修。WARN 需要看：它可能是一个真实问题，也可能是这套库有意接受的代价。

## 不检查什么

- 外部 URL 是否存活（需要网络，且常被反爬误伤）
- Markdown 链接（`[文字](url)`）是否可达
- 附件是否存在（`![[图片.png]]` 会跳过）
- 内容是否准确、是否有价值
- 两篇笔记是否说了同一件事
- 标签是否语义重复
- 文件名是否好读

这些需要人或另外的工具。审计的边界写清楚，比假装全能更有用。

## 假阳性是怎么处理的

脚本已经内置这些规则：

- 模板目录整体跳过（占位符、种子状态不报错）
- `01 收件箱` 允许没有 frontmatter
- `99 归档` 不参与活跃区检查
- 围栏代码块、行内代码不参与链接抽取
- 以 `❌` / `✅` / `⚠` 开头的行不参与链接抽取（规范文档里的反例）
- 表格里的 `\|` 还原为 `|` 后再解析
- 同名文件不猜，直接报歧义
- `[[#标题]]` 同文件锚点支持
- `[[^块ID]]` 块引用跳过锚点校验
- 块引用别名 `[[文件|显示名]]` 正确剥离

如果你遇到新的假阳性，**先加一个单元测试**，再改解析逻辑。否则下一次改动会把旧问题带回来。

## 怎么加一条检查

1. 在 `tools/kb_audit.py` 里写一个 `check_xxx(vault) -> CheckResult` 函数，参考 `check_links`。
2. 在 `run_audit()` 的 `checks` 列表里注册。
3. 在 `tools/tests/test_audit.py` 加一个最小复现。
4. 更新本页的检查项列表。

不要把「内容质量」写进审计。那会让 FAIL 变成主观判断。
