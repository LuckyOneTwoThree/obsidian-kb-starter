# 受控词表

`type`、`status`、`source_type` 只能取本页列出的值。`tools/kb_config.json` 是机器可读版本；改这里时同步改配置，否则「写的」和「查的」会分叉。

## type：它是什么

| 值 | 含义 | 通常所在 |
|---|---|---|
| `index` | 索引 / 导航 / 说明页 | `00 索引`、各目录说明 |
| `inbox` | 收件箱在制品 | `01 收件箱` |
| `reading` | 阅读笔记（对外部来源的消化） | `02 阅读笔记` |
| `topic` | 主题笔记（我的判断 + 因果链） | `03 主题笔记` |
| `evergreen` | 常青卡（原子知识） | `04 常青笔记` |
| `project` | 项目主页 | `05 项目/年份/项目名/` |
| `project_doc` | 项目内文档（方案、过程、复盘） | 项目目录内 |
| `review` | 复盘 / 周回顾 | `03 主题笔记` 或项目目录 |
| `writing` | 对外发布文章 | 升级后使用 |
| `area` | 长期领域主页 | 升级后使用 |
| `area-goal` | 年度目标 | 升级后使用 |
| `reference` | 参考资料 / 网页存档 | `07 资料库` |
| `resource` | 资源清单 / 工具表 | `07 资料库` |
| `task` | 任务卡 | 按需 |
| `log` | 日志 / 流水 | 按需 |
| `template` | 模板文件 | `07 资料库/D 模板` |

> Lite 版没有 `06 长期领域`，所以 `area` / `area-goal` 暂时用不到，但保留在词表里，升级时不需要改工具。

## status：它在流程的哪一步

| 值 | 含义 | 适用于 |
|---|---|---|
| `active` | 页面有效在用 | 仅 `index` / 导航类（目录说明、主页、索引） |
| `待阅读` | 来源还没读 | `reading`、收件箱里的待读 |
| `待整理` | 已捕获，未归位 | `inbox` |
| `待提炼` | 材料已读，判断未成形 | `topic` |
| `已提炼` | 判断与因果链已写完 | `topic` |
| `草稿` | 内容已成形，但作者未确认 | `evergreen`、`project_doc`、`review`、`writing` |
| `已沉淀` | 作者确认可复用 | `evergreen`（`reading` 表示来源已消化完） |
| `需复习` | 结论依赖时效证据，需复核 | `reading` / `topic` / `evergreen` |
| `待启动` | 项目已立项，未动手 | `project` |
| `进行中` | 正在推进 | `project`、`project_doc`、`task` |
| `暂停` | 主动停下，写明重启条件 | `project` |
| `已完成` | 交付物已产生 / 复盘已写完 | `project`、`project_doc`、`review`、`task` |
| `已发布` | 文章已发布 | `writing` |
| `已归档` | 冷存储，不再主动维护 | 任意，移入 `99 归档` 时必填 |

### 三个容易混的边界

- `active` ≠ `进行中`。前者只描述「这个导航页在用」，后者描述「项目在推进」。
- `已沉淀` ≠ `已提炼`。前者是常青级「作者确认的判断」，后者是主题级「判断已写完」。
- `已沉淀` 在 02 与 04 不是同一个意思：02 = 来源已消化完；04 = 作者确认。
- `草稿` ≠ 半成品垃圾。它是**内容已成形、但作者还没背书**的诚实状态，尤其适合 AI 协作产出。

### 合法流转

```text
reading:   待阅读 → 已沉淀
                    ↘ 需复习 → 已沉淀 / 降级

topic:     待提炼 → 已提炼
                    ↘ 需复习 → 已提炼 / 降级

evergreen: 草稿 → 已沉淀
                  ↘ 需复习 → 已沉淀 / 降级为草稿

project:   待启动 → 进行中 → 已完成
                    ↘ 暂停 → 进行中 / 已归档
```

**不允许**为了清队列直接跳状态。状态是判断的结果，不是整理的结果。

## source_type：内容从哪来

| 值 | 含义 |
|---|---|
| `原创随笔` | 自撰想法、感想、构想，无外部来源 |
| `原创方法论` | 自撰的成体系方法论 |
| `原文精读` | 直接读原文并逐段消化（含网页抓取） |
| `阅读笔记` | 从既有 02 阅读笔记二次提炼 |
| `文章` / `书籍` / `课程` / `播客` / `视频` / `论文` / `网页` | 外部来源的形态 |
| `对话` | 与 AI 或人的对话产出 |
| `手动采集` / `自动化采集` | 摘要或剪藏管线 |
| `GitHub 仓库` | 内容源自某个代码仓库 |

**必须登记**：`reading`、`topic`、`evergreen`、`project`。

**可以留空**：目录说明与索引、收件箱、模板、归档、`project_doc`、`review`。

**不要伪造来源。** 自撰内容写 `原创随笔` / `原创方法论`，不要硬编一个不存在的文章。缺来源可以补，假来源会污染整个溯源链。

## 可选字段

| 字段 | 用于 | 说明 |
|---|---|---|
| `form` | `evergreen` | `概念` / `原则` / `模型` / `方法` / `判断` / `金句`；缺失会给 WARN |
| `source_url` | `reading` | 原文链接；失效时保留文字出处 |
| `author` | `reading` | 作者 |
| `area` | 全部 | `工作` / `学习` / `生活` 等 |
| `project` | `project_doc` / `review` | 所属项目名 |
| `start_date` / `end_date` | `project` | 起止日期 |
| `platform` | `writing` | 发布平台 |
| `endorsed` | `topic` / `evergreen` | 作者确认「这是我的判断」的日期；**AI 不得代填** |
| `evidence_as_of` | `reading` / `topic` / `evergreen` | 证据基线日；`需复习` 必填 |

### endorsed 与 evidence_as_of 的分工

- `evidence_as_of` 问：**证据新不新鲜？**
- `endorsed` 问：**这个判断是不是你的、你现在还认吗？**

两者正交。一篇证据很新的 AI 调研可能没人确认；一篇证据停在三个月前的老判断可能至今成立。

Lite 版不强制 `endorsed`，也不把它放进工作台队列。它是给认真使用者的进阶字段，不是第一天的负担。

## tags：跨目录的主题

标签只表达**主题**，不表达目录或状态。

**禁用**：`收件箱`、`阅读笔记`、`主题笔记`、`常青笔记`、`项目`、`索引`、`待阅读`、`待整理`、`待提炼`、`需复习`、`已归档`。

**命名**：

- 中文主题词优先：`远程协作`、`决策`、`信息架构`
- 一个标签一个概念，不要用 `、` 把多个主题塞进去
- 优先复用已有标签；新标签先想想是不是同义词
- 示例内容统一带 `示例`，方便一次删除

**建议起步标签**：`AI`、`产品`、`工作方法`、`写作`、`决策`、`远程协作`、`信息架构`、`复盘`。

## frontmatter 最小集

```yaml
---
type: reading
status: 待阅读
tags: []
created: 2026-10-20
updated: 2026-10-20
---
```

所有非豁免笔记都要有这四个字段。`01 收件箱`、`07 资料库/D 模板`、`99 归档` 豁免；仓库级文件（`README.md` / `CHANGELOG.md` / `CONTRIBUTING.md` / `SECURITY.md` / `CODE_OF_CONDUCT.md` / `CLAUDE.md` / `TROUBLESHOOTING.md` / `MIGRATION.md` / `RELEASING.md`）也豁免。

## 工具怎么校验

`tools/kb_audit.py` 会检查：

- 文件是否能按 UTF-8 读取
- 四个必填字段是否存在
- `type` / `status` / `source_type` 是否在词表内
- `form` 是否在词表内
- `status` 是否与 `type` 兼容
- `type` 是否与所在目录匹配
- `需复习` 是否填了 `evidence_as_of`
- 是否使用了禁用标签
- 文件名是否全库唯一（WARN）
- 笔记嵌入 `![[笔记]]` 是否存在
- `source_type` / `area` / `form` 是否与 02/03/04 子目录一致（WARN）
- 项目路径/命名、归档位置、已完成复盘（WARN）
- 收件箱日期笔记是否超过 14 天（WARN）
- 别名是否与别的文件名冲突、链接大小写是否一致（WARN）

它**不检查**内容质量、事实准确性、外部链接是否存活、附件是否存在。那些需要人或另外的工具。
