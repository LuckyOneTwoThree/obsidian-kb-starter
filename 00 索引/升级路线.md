# 升级路线

**不要因为「以后可能会用」而提前加结构。** 每一阶段都有触发条件；没到条件就停在当前阶段。

## 阶段 0：Starter / Lite（现在）

> Starter 是模板名；Lite 指当前阶段 0 的形态。v0.1 两者指同一个东西。

- 8 个顶层目录，无 `06 长期领域`
- 7 个模板
- 4 个工作台查询块
- 配置驱动的审计 + 实例化工具
- 示例内容可用 `tools/kb_clean_demo.py` 清理（默认 dry-run）

适合：刚开始、输入还不稳定、需要一个低摩擦闭环的人。

## 阶段 1：有真实输入之后

**触发条件**（全部满足）：

- 连续 30 天有捕获
- 至少 5 张常青卡
- 至少 1 次对外输出
- 你开始觉得「有些事没有项目、也没有明确结束，但需要长期跟」

**加什么**：

1. **`06 长期领域`**
   - 每个领域一个 `<领域名>主页.md`，`type: area`，`status: active`
   - 年度目标 `<年份>-<领域名>-年度目标.md`，`type: area-goal`
   - 领域的判据是「长期责任」，不是「兴趣」
2. **写作与发布**
   - `06 长期领域/E 写作/A 发布文章/`
   - `发布台账.md`：标题、平台、日期、链接、源笔记
   - 文章 `type: writing`，状态 `草稿 → 已发布`
3. **项目复盘模板**
   - 已有 [[_模板_复盘]]，在项目结束时强制写一次
   - 复盘里回答：目标 vs 结果、做对了什么、做错了什么、下次动作

**成本**：多一个顶层目录、两三个模板、每月多一次领域回顾。

## 阶段 2：卡片开始变多之后

**触发条件**：

- 常青卡超过 30 张
- 同一主题下出现 3 张以上互相引用的卡
- 开始出现「这张卡和那张卡是什么关系」的问题
- 复习队列连续两个月有真实条目

**加什么**：

1. **合集**
   - 在 `04 常青笔记/合集/` 下按主题建合集
   - 合集只收**短判断/短原则**；完整模型、方法仍独立成篇
   - 合集内每个小节一个锚点，卡片用 `[[合集#小节]]` 指向
2. **`endorsed` 强制化**
   - 在 `kb_config.json` 增加规则：`04` 的 `已沉淀` 必须带 `endorsed`
   - 先跑一个月 WARN，再改 FAIL
3. **`evidence_as_of` 复习队列**
   - 所有 `需复习` 必须有 `evidence_as_of`（Lite 已校验）
   - 工作台按证据龄排序，最旧优先
4. **小节级覆盖报告**
   - 只对「批次阅读笔记」启用
   - 统计有哪些原文小节被 03/04 真实引用
   - 目标不是 100%，而是看见「读了但没转化」的部分
5. **标签收敛**
   - 合并同义标签
   - 删除只用过一次、且不是专有名词的标签

**成本**：合集需要维护层级；`endorsed` 强制化会增加每次成卡的心理成本；覆盖报告需要批次笔记有稳定的 `##` 结构。

## 阶段 3：AI 深度协作

**触发条件**：

- 每周有多次 AI 协作整理
- 开始出现「AI 改了但我不知道改了什么」的问题
- 库已经大到单次会话读不完

**加什么**：

1. **协作契约扩展**
   - `AGENTS.md` 从约 140 行扩到 200–300 行
   - 增加任务剧本：批量消化、跨笔记合并、索引重建、冲突裁决
2. **维护日志独立**
   - `.workbuddy/maintenance_log.md` 或 `00 索引/维护日志.md`
   - 只记「哪一轮改了什么、依据是什么、哪些结论被推翻」
   - 不把流水写回 `AGENTS.md`，避免初始化预算被历史吃掉
3. **CI 审计**
   - GitHub Actions 在每次 push 跑 `python3 tools/kb_audit.py`
   - 默认只对 FAIL 阻断；如果你要求零 WARN，再改用 `--strict`
   - 把 `--json` 报告存档，WARN 留给人判断
4. **外部链接与附件检查**
   - 单独脚本，不进主审计
   - 区分「真死链」与「反爬 403」
5. **更强的查询**
   - 原生查询不够用时，再考虑 Dataview / Bases
   - 先写清楚「哪个视图不够用」，再引入插件

**成本**：CI 需要维护；外部链接检查会产生大量假阳性；插件会带来版本与迁移风险。

## 每次升级前问四个问题

1. **现在的具体痛点是什么？** 不能是「感觉不够完整」。
2. **新结构会让哪一步变慢？** 任何结构都有摩擦。
3. **触发条件到了吗？** 没到就记在待办里，不动手。
4. **能回滚吗？** 能归档、能删配置、能恢复模板吗？

## 不建议的升级

- 为每个主题建一个目录
- 为每种来源建一套独立模板
- 每天自动抓 20 篇文章
- 用 AI 自动给所有笔记补双链
- 用仪表盘替代工作台
- 在没有输入的时候增加审计维度

这些做法在源库里都出现过，没有一个解决了「输入断流」。
