# 示例导览

库里的示例全部是虚构的，主题是「远程团队协作」。所有示例笔记都带 `示例` 标签（日记没有 frontmatter，但文件名、注释与内容也明显是示例）。

**示例的作用是让你看到一条完整的知识流，不是让你保留它。** 读完 [[开始使用]] 后，可以按本页末尾的步骤一次删掉。

## 建议阅读顺序

1. **捕获** — `01 收件箱/A 临时想法/2026-10-12.md`
   一句话记录，没有 frontmatter。看它有多轻。
2. **待整理** — [[示例-远程协作的三个断层]]
   两天后回看，发现这句话可以展开，但还不确定归属，于是留在 D 待整理。
3. **来源消化** — [[示例-远程团队为什么需要写决策日志]]
   找到一篇（虚构的）文章，只做来源消化：核心观点、原文摘录、我的转述。这里**不下最终判断**。
4. **主题判断** — [[示例-远程团队的信息架构]]
   把来源和自己的观察合成一个判断，写出因果链。证据层只放指向 02 的锚点，不复制原文。
5. **原子卡（判断）** — [[示例-远程团队的瓶颈是可回放的决策上下文]]
   从主题笔记里抽出一句能独立成立的判断。作者已确认，所以 `status: 已沉淀`、`endorsed` 有日期。
6. **原子卡（方法）** — [[示例-决策日志的最小字段]]
   同一主题下的操作方法是草稿：内容成形，但作者还没确认。注意它**没有**写 `已沉淀`。
7. **项目** — [[2026-周报改造-项目主页]] 与 [[2026-周报改造-方案]]
   判断进入行动。项目在捕获之前已经启动，这里看的是判断如何进入一个正在进行的项目；项目主页只写目标、关键结果与下一步，方案放在项目内，不另起主题笔记。
8. **回顾** — [[2026-W42-周回顾]]
   每周 30 分钟的收口动作：输入、判断变化、输出、下周一件最重要的事。

## 建议观察的四件事

- **同一判断只沉淀一次**：主题笔记里写因果链，常青卡里只留可复用结论，两边用双链连接，不复制段落。
- **状态是诚实的**：方法卡仍是草稿，没有为了好看改成已沉淀。
- **空队列是警报**：工作台为空时，不代表做完了，代表没有新输入。
- **模板是实例种子**：模板里的 `status` 是新建笔记的初始状态，不是模板自己的状态。

## 怎么删掉示例

推荐用脚本，先看它准备删什么：

```bash
python3 tools/kb_clean_demo.py            # 只预览，不写入
python3 tools/kb_clean_demo.py --apply    # 删除示例并清理索引，先自动备份
```

脚本会删除示例笔记与 `2026-周报改造` 项目目录，清理 [[笔记索引]]、[[项目总览]]、[[知识库主页]]、[[开始使用]]、各目录说明和 README 里的示例段，并在 `.backup/` 留一份副本。

如果想手工删，顺序是：

1. 删除所有带 `示例` 标签的笔记（Obsidian 搜索 `tag:#示例`）。
2. 删除 `01 收件箱/A 临时想法/2026-10-12.md`。
3. 删除 `05 项目/2026/2026-周报改造/` 整个目录。
4. 清空 [[笔记索引]] 与 [[项目总览]] 里的示例行。
5. 删除本页，并从 [[知识库主页]] 与 [[开始使用]] 的导航里移除指向本页的那一行。
6. `02`–`05` 四个目录说明里的示例路径是**行内代码**，删掉示例不会产生断链；顺手把那几行也删掉即可。
7. 跑 `python3 tools/kb_audit.py`，确认没有断链与孤儿。

删完后，这个库就是一张白纸，但结构、模板、规则和审计工具都还在。
