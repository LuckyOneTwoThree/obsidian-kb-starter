# 知识库地图

## 一句话结构

**目录表示「它在流程的哪一步」，双链表示「它和什么有关」，标签表示「它跨目录属于什么主题」。**

## 目录

```text
00 索引      导航、工作台、规则文档
01 收件箱    还没判断归属的东西
  A 临时想法   一句话捕获、当天日记
  B 摘录剪藏   网页、书摘、对话片段
  C 待阅读     稍后要读的来源
  D 待整理     读了/想了，但还没归位
02 阅读笔记  对外部来源的消化（书 / 文章 / 课程 / 其他）
03 主题笔记  围绕一个主题的「我的判断」与因果链
04 常青笔记  可独立复用的原子知识（概念/原则/模型/方法/判断/金句）
05 项目      有交付物的行动，按年份组织
07 资料库    模板与附件（不是笔记内容）
99 归档      不再活跃但保留溯源的文件
```

没有 `06 长期领域`。这是 Lite 版的刻意省略：先用项目把「有截止日的事」跑起来，等真的需要年度目标与长期责任，再按 [[升级路线]] 加回。

## 知识怎么流动

```text
捕获（01）
  ↓ 判断它是什么
外部来源 → 02 阅读笔记 → 03 主题笔记 → 04 常青卡
                              ↘ 05 项目 / 写作
```

三条硬规则：

1. **02 只放来源的消化，不放自己的结论。**
2. **03 必须写出「我的判断」和因果链，不能只列原文目录。**
3. **04 一张卡只放一个判断，并且能脱离原文独立成立。**

## 东西该往哪放

| 你手里的东西 | 放哪 | 初始状态 |
|---|---|---|
| 刚想到的一句话 | `01 收件箱/A 临时想法/` | 可无 frontmatter |
| 一段摘录、网页剪藏 | `01 收件箱/B 摘录剪藏/` | `待整理` |
| 想读但还没读的文章 | `01 收件箱/C 待阅读/` | `待阅读` |
| 读了、想了，但没归位 | `01 收件箱/D 待整理/` | `待整理` |
| 对一本书/一篇文章的消化 | `02 阅读笔记/` 对应子目录 | `待阅读` → `已沉淀` |
| 一个主题下我的判断 | `03 主题笔记/` 对应领域 | `待提炼` → `已提炼` |
| 一句可复用的判断/原则/模型 | `04 常青笔记/` 对应子目录 | `草稿` → `已沉淀` |
| 有交付物的行动 | `05 项目/年份/项目名/` | `待启动` → `进行中` |
| 模板、附件 | `07 资料库/` | — |
| 不再活跃但值得留痕 | `99 归档/` | `已归档` |

## 命名

- **文件名必须全库唯一**。同名文件会让 `[[链接]]` 指向不确定的那一个，而且不会报错。
- 项目主页统一叫 `<项目名>-项目主页.md`，方案叫 `<项目名>-方案.md`，不要制造一堆同名「项目主页」。
- 目录说明统一叫 `<目录名>说明.md`，例如 [[收件箱说明]]、[[阅读笔记说明]]。
- 文件名用中文主题词，不用日期前缀；日期放在 frontmatter 里，日记除外。

## 每篇笔记的最小 frontmatter

```yaml
---
type: reading
status: 待阅读
tags: []
created: 2026-10-20
updated: 2026-10-20
---
```

`type` 决定它是什么，`status` 决定它在流程的哪一步。两者都只能取 [[受控词表]] 里的值。

## 规则放在哪

- 人看：[[开始使用]]、[[维护手册]]、[[受控词表]]
- AI 看：[[AGENTS]]
- 机器看：`tools/kb_config.json`

改规则时三处一起改，否则「写的」和「查的」会分叉。
